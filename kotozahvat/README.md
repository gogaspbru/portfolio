# Котозахват

Браузерная игра: вводишь адрес сайта — он превращается в разрушаемый уровень-платформер,
а рыжий пиксельный кот разносит его по пикселям. Работает на компьютере и на телефоне.

Сделано в [goga.spb.ru](https://goga.spb.ru). Развлекательный проект, без монетизации.

> **Статус:** этап 1 (игра на демо-сайте) и этап 2 (настоящие сайты через PHP-загрузчик
> на обычном хостинге) готовы. Этап 3 (шеринг, OG-картинки, полировка) — впереди.

## Быстрый старт

Нужен Node.js 20+ (проверялось на 22).

```bash
cd kotozahvat
npm install
npm run dev          # http://localhost:5173 — разработка с горячей перезагрузкой
```

Полезные параметры адреса:

| Параметр | Что делает |
|---|---|
| `?url=demo` | сразу запустить демо-уровень, без стартового экрана |
| `?debug=1` | fps, число осколков, хитбокс кота, путь автопилота; игра доступна как `window.__kot` |
| `?bench=6000` | бенчмарк: держать столько летящих осколков одновременно (смотрите fps внизу слева) |
| `?sprites=export` | показать и скачать текущий спрайт-лист кота как шаблон |

## Сборка и выкладка фронтенда

```bash
npm run build        # проверка типов + сборка в ../kot (корень репозитория-портфолио)
npm run preview      # посмотреть собранную версию локально
```

Сборка кладётся в папку `kot/` в корне репозитория, пути относительные — после выкладки
сайта-портфолио игра открывается по адресу `goga.spb.ru/kot/`. Папка `kot/` коммитится
вместе с остальным сайтом (как и `index.html` портфолио — отдельного CI нет).

## Выкладка на хостинг (FTP)

Всё, что нужно, — папка `kot/` целиком (после `npm run build`, либо из готового архива).
Залейте её в корень сайта рядом с `index.html`, чтобы получилось `…/kot/index.html`
и `…/kot/api/fetch.php`. Отдельного сервера не нужно — хватает PHP 7.4+ с curl,
который есть на обычном виртуальном хостинге (проверялось локально на PHP 8.4;
на конкретном хостинге проверьте сами — см. ниже).

**Проверка после заливки:** откройте `https://goga.spb.ru/kot/api/fetch.php?mode=check`.
Должно быть: `"curl": true`, `"кеш доступен для записи": true`, `"выход в интернет": "ok"`.
Если кеш недоступен — выставьте папке `kot/api/cache` права 755 (или 775) в FTP-клиенте.

## Как настоящий сайт становится уровнем (этап 2)

Сервера с браузером у нас нет, поэтому работа поделена:

1. **PHP-загрузчик** `client/public/api/fetch.php` (в сборке — `kot/api/fetch.php`) скачивает
   HTML страницы, а потом по запросу — её картинки, стили и шрифты.
2. **Браузер игрока** убирает из страницы скрипты и всё активное, раскладывает её в невидимом
   iframe шириной 1280 (без права запускать скрипты), собирает прямоугольники элементов
   (`shared/extract-elements.js` — тот же сборщик, что у демо) и перерисовывает страницу
   в картинку библиотекой html2canvas-pro (грузится только когда нужна, ~73 КБ gzip).

**Безопасность загрузчика:** только http/https и порты 80/443; защита от SSRF — адрес резолвится,
приватные, локальные и служебные IP (127/8, 10/8, 172.16/12, 192.168/16, 169.254/16, 100.64/10,
::1, fc00::/7, fe80::/10 и др.) запрещены, соединение идёт строго на проверенный IP (без
повторного DNS), каждый редирект проверяется заново; таймаут 12 с, лимит 3 МБ на страницу
и 5 МБ на файл; лимит запросов с одного IP (15 страниц и 1500 файлов за 10 минут);
кеш ровно на сутки; чужой HTML никогда не отдаётся с нашего домена как страница.
Запросы с чужих сайтов отклоняются (защита от использования как бесплатного прокси).
Настройки — константы в начале `fetch.php`.

**Ограничения (честно):**
- это перерисовка, а не снимок браузера: шрифты и сложные эффекты могут немного отличаться;
- сайты, которые целиком рисуются скриптами (многие React/Vue-приложения), выходят пустыми —
  игра так и пишет: «Этот сайт рисуется скриптами…»;
- часть сайтов закрыта от роботов (Cloudflare и т. п.) — будет «Сайт не пустил котика».

**Проверка без интернета:** `npm run build && npm run live-test` — поднимает тестовые сайты из
`test-sites/` (внешний CSS, картинки, windows-1251, редиректы, сайт на скриптах) и проверяет
загрузчик и игру целиком. Для этого теста загрузчику разрешается localhost через переменную
окружения `KOTOZAHVAT_DEV_ALLOW_LOCAL=1` — на хостинге её нет.

**Разработка с настоящими сайтами:** в одном терминале `npm run php` (нужен php в системе),
в другом `npm run dev` — Vite перенаправит `/api` на PHP.

## Управление

**Компьютер:** A/D или стрелки — бег; пробел (W, ↑) — прыжок, ещё раз в воздухе — кульбит;
держать прыжок — кот лезет вверх по «изнанке» сайта; S (↓) — спрыгнуть сквозь платформу;
мышь — куда смотрит кот; клик — удар лапой; зажатая кнопка — точить когти.

**Телефон:** тап по месту — кот сам бежит, прыгает и лезет туда (поиск пути по платформам);
тап по блоку — лапой (если блок далеко, кот сам подойдёт и ударит); долгое нажатие на блок — точить когти (если блок далеко,
кот сначала подойдёт); свайп вниз — спрыгнуть; свайп вверх — прыжок.

## Как устроено

- **Уровень** (`client/src/level/Level.ts`) — сетка клеток 8×8 поверх скриншота. Каждая клетка
  принадлежит верхнему элементу страницы, который её накрывает. Стоять можно на твёрдой клетке,
  над которой пусто, — поэтому верхние грани элементов автоматически становятся платформами,
  а отколотые куски создают новые. Платформы пропускают снизу (как в классических платформерах).
- **Здоровье** элемента = множитель типа × (base + k·√площади). Удар лапой снимает здоровье
  всем элементам в радиусе и сразу откалывает клетки в точке удара; когти наносят урон со временем
  и оставляют царапины. На порогах здоровья появляются трещины, на нуле элемент осыпается.
- **Осколки и куча** (`client/src/debris/Debris.ts`) — летящие осколки хранятся в типизированных
  массивах без аллокаций в кадре и рисуются через один `ImageData` размером с экран. Упавший осколок
  «впекается» в кучу (карта высот + маленькая картинка) и перестаёт стоить что-либо. Куча сыпется
  как песок, по ней можно ходить. Высота кучи ограничена (`debris.maxPileHeight`).
- **Прогресс** = доля разрушенных клеток. После `destruction.winThreshold` (по умолчанию 97 %)
  остаток осыпается сам, кот садится умываться, затем финальный экран.
- **Ввод** (`client/src/input/`) — клавиатура, мышь и тачи превращаются в общие команды `Commands`.
  Автопилот для телефона (`client/src/nav/`) выдаёт такие же команды: граф площадок + Дейкстра,
  путь перестраивается при каждом приземлении.
- **Рендер** — Canvas 2D, физика с фиксированным шагом 60 Гц, отрисовка с частотой экрана.
  Передний план нарезан на плитки 256×256 и рисуется только видимая часть.

### Почему Canvas 2D, а не Phaser

Главное в игре — сетка разрушения, пиксельные осколки и куча — Phaser из коробки не даёт,
их всё равно пришлось бы писать вручную. Без движка сборка весит ~50 КБ (≈18 КБ gzip),
и весь горячий код под контролем, что важно для телефонов.

## Настройки игры

Все параметры — в одном файле **`client/src/config.ts`**. Размер кота — константа `CAT_SIZE`
в его начале (1 — маленький, сейчас 3): от неё зависят спрайт, хитбокс, дальность лапы, прыжок.
Остальное: скорость бега, сила прыжка и кульбита,
лазанье, урон лапы и когтей, здоровье блоков по типам, число осколков, высота кучи, порог победы,
масштаб камеры на телефоне и т. д. У каждого параметра есть комментарий.

Масштаб на телефоне: уровень шириной 1280 px на экране телефона становится очень мелким,
поэтому `camera.minZoom` (по умолчанию 0,55) не даёт уменьшать сильнее — камера приближает и
ездит за котом. Поставьте `0`, чтобы всегда видеть всю ширину сайта.

## Свой кот (замена спрайтов)

Встроенный кот нарисован кодом (`client/src/cat/proceduralCat.ts`). Чтобы заменить:

1. Откройте игру с `?sprites=export` и скачайте `cat.png` и `cat.json` — это шаблон.
2. Перерисуйте кадры в `cat.png` (размер кадра и сетку не меняйте, или поправьте их в JSON).
3. Положите оба файла в `client/public/sprites/` и пересоберите.

Формат `cat.json`:

```json
{
  "frameWidth": 32, "frameHeight": 26, "columns": 8,
  "anchorX": 16, "anchorY": 25,
  "scale": 2,
  "animations": {
    "idle":    { "frames": [0, 1, 2, 3], "fps": 4,  "loop": true },
    "run":     { "frames": [4, 5, 6, 7, 8, 9], "fps": 14, "loop": true }
  }
}
```

Кадры нумеруются слева направо, сверху вниз. Кот в кадрах смотрит **вправо**, `anchorX/anchorY` —
точка «лапы на земле». Анимации: `idle`, `run`, `jump`, `fall`, `flip` (кульбит, спрайт вращается),
`land`, `paw`, `scratch`, `climb`, `sit`, `wash`. Недостающие заменяются на `idle`.

## Демо-уровень

`demo/page.html` — вымышленный сайт «Котовости». Скриншот и разметку делает тот же сборщик
элементов, что будет на сервере (`shared/extract-elements.js`):

```bash
npm run demo         # → client/public/demo/demo.png + demo.json
```

Если Playwright не находит браузер: `CHROMIUM_PATH=/путь/к/chrome npm run demo`.

## Автопроверка

`scripts/playtest.mjs` — бот, который проходит демо до финального экрана настоящими тапами
(эмуляция Pixel 7) или кликами мыши:

```bash
npm run build && npx vite preview --port 4173 &
node scripts/playtest.mjs              # телефон
node scripts/playtest.mjs --desktop    # компьютер
```

## Структура

```
kotozahvat/
  client/                 фронтенд (Vite + TypeScript)
    index.html
    public/demo/          демо-уровень
    public/sprites/       сюда — свой cat.png + cat.json (необязательно)
    public/api/fetch.php  PHP-загрузчик сайтов (едет в сборку как kot/api/)
    src/
      config.ts           все игровые параметры
      main.ts             экраны и сценарий: старт → загрузка → игра → финал
      Game.ts             цикл, симуляция, рендер
      api.ts              загрузка уровня (демо / настоящий сайт)
      capture/            настоящий сайт → уровень: очистка HTML, iframe, html2canvas
      level/              сетка, урон, трещины, царапины
      debris/             осколки и куча
      cat/                физика кота, спрайты
      abilities/          «оружия»: лапа, когти (сюда же новые)
      input/              клавиатура, мышь, тачи → команды
      nav/                автопилот: граф площадок и поиск пути
      render/             камера, эффекты, плиточный холст
      ui/                 стили и DOM-помощники
  shared/                 общий код клиента и сервера
    types.ts              формат уровня
    extract-elements.js   сбор прямоугольников элементов в браузере
  demo/page.html          исходник демо-сайта
  test-sites/             локальные тестовые сайты для live-test
  scripts/                генератор демо, автопроверки, бенчмарк
```

## Задел на будущее

- **Новые «оружия»** (комок шерсти, мяу-волна, прыжок-бомбочка, клубок, «позвать банду») —
  новый класс с интерфейсом `Ability` в `client/src/abilities/` и строка в `Game.abilities`.
- **Помеха — робот-пылесос** — отдельная сущность, которая получает те же `Commands`, что и кот
  (можно переиспользовать автопилот `Navigator`).
- **Мультиплеер** — симуляция отделена от ввода: по сети достаточно передавать `Commands`.
